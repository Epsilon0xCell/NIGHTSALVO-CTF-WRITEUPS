# H1

- **Event:** Google CTF 2021
- **Category:** crypto
- **Difficulty:** not rated in the handout

## Summary

Two people, Alice and Bob, do ECDH on a 512-bit curve, sign their messages with ECDSA, and encrypt them with AES under a key hashed from the shared secret. Alice's third message contains the flag. The whole thing falls over because of the nonce generator in `Sign`: every nonce is built from only 16 random bytes, each one repeated across a 4-byte block. Bob signed two messages I know the plaintext of, so his private key comes out of a hidden number problem lattice. Alice's public key comes from ordinary ECDSA public key recovery on her first signature. After that the shared secret, the AES key and the flag message are just arithmetic.

## First look

The player files are `2021/quals/crypto-H1/attachments/chall.py` and `output.txt`, both links to the files under `src/` in the official google/google-ctf archive. The output file has four signed, encrypted messages:

```text
Alice -> Bob: (r, s, ciphertext)     message: "Hello Bob."
Bob -> Alice: (r, s, ciphertext)     message: "Hello Alice."
Alice -> Bob: (r, s, ciphertext)     message: "Dinner tonight? ... here is the flag: ..."
Bob -> Alice: (r, s, ciphertext)     message: "Dinner sounds good. Thanks for the flag."
```

Ciphertext sizes from the output: 16, 16, 128 and 48 bytes once the integers are converted back. The public keys are never printed, which matters later.

The part of `chall.py` that matters is the random number generator:

```python
def RNG(nbits, a, b):
    nbytes = nbits // 8
    B = os.urandom(nbytes)
    return a * sum([B[i] * b ** i for i in range(len(B))]) % 2**nbits
```

Private keys use `RNG(nbits, 1, 256)`, which is just a uniform little endian integer, no flaw there. Signatures use something else entirely.

## What I tried first

My first idea was to attack Alice, because she signs the flag message. That goes nowhere on its own: for her second signature the message hash covers the unknown flag, so I cannot even write down the ECDSA equation for it. She only gives me one usable equation, and one equation in her key plus a structured nonce has about 2^128 solutions. Dead end, and it took me an hour to accept it.

I also wasted time checking the shared secret side first. The encryption key is `sha256(str(x))` of the ECDH x coordinate, and with neither private key and neither public key printed, there is nothing to grab onto from the ciphertexts alone.

The useful observation was about who signs what, twice, over known text: Bob. `Hello Alice.` and `Dinner sounds good. Thanks for the flag.` are both fully known, so Bob gives me two clean equations.

## The breakthrough

Look at the nonce call: `RNG(n.bit_length(), 16843009, 4294967296)`. The curve order `n` has 512 bits, so the modulus inside the generator is 2^512, the base is 2^32, and only the terms with `32 * i < 512` survive the reduction. That is the first 16 bytes of the 64 random bytes; the other 48 bytes are thrown away by the modulo.

Then the multiplier: 16843009 is `0x01010101`. Multiplying a byte `B[j]` by it gives the byte repeated in all four bytes of a 32-bit block, with no carry out of the block, and the blocks sit side by side at offsets `32 * j`. So the whole nonce is

```text
k = sum over j of B[j] * 0x01010101 * 2^(32*j),   j = 0..15, B[j] in [0, 255]
```

64 nonce bytes, only 16 unknown values, each one printed four times in a row.

Each Bob signature gives `k = u + t * db (mod n)` with `u` and `t` known from the message hash and the signature values. Substituting the block form of `k` turns that into a hidden number problem with 32 small unknowns (the bytes) and one big one (Bob's key `db`). I built the standard embedding lattice over the coordinates `[B1 bytes, B2 bytes, db, e1, e2, embedding]`, with the byte coordinates weighted by 2^512, the key coordinate by 2^8 and the equation coordinates by 2^1024 so the true solution is the short vector. Plain double precision GSO overflowed on those weights with an `infinite number in GSO` error; switching fpylll to long double arithmetic fixed it, and a single LLL pass found the vector. No BKZ was needed.

For Alice, the missing piece turned out to be standard: ECDSA public key recovery. From her first signature and the known message `Hello Bob.`, the point `R` has x coordinate `r` (two choices for y, since the field prime is 3 mod 4 and square roots are one exponentiation), and her public key is `r^{-1} (s * R - z * G)`. That gives 2 candidates. The shared secret from the wrong candidate fails to decrypt her first ciphertext; the right one gives back `Hello Bob.` on the first try, which pins it down before I ever touch the flag message.

## Solve

The full solve script. It loads the curve arithmetic from the player source, builds the 36 coordinate embedding lattice over Bob's two signatures, reduces it with fpylll in long double precision, recovers Alice's public key from her first signature, and decrypts her messages with the shared secret:

```python
#!/usr/bin/python3
"""Solve for Google CTF 2021, crypto, H1.

Player files used (official google/google-ctf archive):
  2021/quals/crypto-H1/src/chall.py    (attachments/chall.py is a link to it)
  2021/quals/crypto-H1/src/output.txt  (attachments/output.txt likewise)
Local working copies are read from /var/tmp/sweep2/work/h1/.

The bug: Sign() picks its nonce with RNG(nbits, 16843009, 2**32), so
k = 16843009 * sum(B[i] * 2**(32*i)) mod 2**512. Modulo 2**512 only the
first 16 random bytes survive, and 16843009 = 0x01010101 spreads each one
across a full 4-byte block, so every block of 4 nonce bytes is identical:
k = sum_j B[j] * 0x01010101 * 2**(32*j) with only 16 unknown bytes.

Bob signed two known messages, which gives a hidden number problem in
those bytes plus his private key. An embedding lattice (LLL, long double
GSO in fpylll) recovers his key. Alice's public key then comes from plain
ECDSA public key recovery on her first signature, the shared ECDH secret
follows, and the AES key is sha256 of its x coordinate as a string.
"""
import ast
import hashlib
import sys

from cryptography.hazmat.backends import default_backend
from cryptography.hazmat.primitives import padding
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from fpylll import BKZ, GSO, IntegerMatrix, LLL

BASE = "/var/tmp/sweep2/work/h1"

# --- Load the curve code from the player source (skip the flag file read
# --- and everything from the key generation section on).
src = open(f"{BASE}/chall_src.py").read()
head = src.split("# Alice and Bob have their keys:")[0]
head = head.replace("flag = open('flag.txt').read()\n", "")
g = {}
exec(head, g)
mod, a, b, n, G = g["mod"], g["a"], g["b"], g["n"], g["G"]
Multiply, Add, Transform = g["Multiply"], g["Add"], g["Transform"]
p = mod


def z_of(msg: bytes) -> int:
    h = hashlib.sha512(msg)
    return Transform(int.from_bytes(h.digest(), "big"), h.digest_size * 8)


out = []
for line in open(f"{BASE}/output_src.txt").read().strip().splitlines():
    out.append(ast.literal_eval(line.split(": ", 1)[1]))

# Bob's two signatures, over known messages.
(r1, s1, _), (r2, s2, _) = out[1], out[3]
msgs = [b"Hello Alice.", b"Dinner sounds good. Thanks for the flag."]
ts, us = [], []
for (r, s, _c), m in zip([out[1], out[3]], msgs):
    sinv = pow(s, -1, n)
    ts.append(r * sinv % n)   # k = u + t*d (mod n)
    us.append(z_of(m) * sinv % n)
t1, t2 = ts
u1, u2 = us

# Nonce block constants: C[j] multiplies the unknown byte B[j].
C = [0x01010101 * (1 << (32 * j)) for j in range(16)]

# --- Embedding lattice, coordinates [B1(16), B2(16), db, e1, e2, emb].
D = 36
wB, wD, wE, K = 1 << 512, 1 << 8, 1 << 1024, 1 << 520
M = IntegerMatrix(D, D)
row = 0
for i in range(16):
    M[row, i] = wB
    M[row, 33] = C[i] * wE
    row += 1
for i in range(16):
    M[row, 16 + i] = wB
    M[row, 34] = C[i] * wE
    row += 1
M[row, 32] = wD
M[row, 33] = -t1 * wE
M[row, 34] = -t2 * wE
row += 1
M[row, 33] = n * wE
row += 1
M[row, 34] = n * wE
row += 1
M[row, 33] = -u1 * wE
M[row, 34] = -u2 * wE
M[row, 35] = K
print("running LLL ...", flush=True)
LLL.Reduction(GSO.Mat(M, float_type="long double"))()


def extract(M):
    for i in range(D):
        emb = M[i, 35]
        if emb in (K, -K) and M[i, 33] == 0 and M[i, 34] == 0:
            sgn = 1 if emb == K else -1
            Bs1 = [sgn * M[i, j] // wB for j in range(16)]
            Bs2 = [sgn * M[i, 16 + j] // wB for j in range(16)]
            db = sgn * M[i, 32] // wD
            if all(0 <= x <= 255 for x in Bs1 + Bs2) and 0 < db < n:
                k1 = sum(C[j] * Bs1[j] for j in range(16))
                k2 = sum(C[j] * Bs2[j] for j in range(16))
                if k1 % n == (u1 + t1 * db) % n and k2 % n == (u2 + t2 * db) % n:
                    return db
    return None


db = extract(M)
if db is None:
    for bs in (20, 30, 40):
        BKZ.Reduction(GSO.Mat(M, float_type="long double"))(BKZ.Param(block_size=bs))
        db = extract(M)
        if db is not None:
            break
assert db is not None, "lattice did not recover Bob's private key"
print("recovered Bob's private key (decimal):", db)


# --- Curve helpers in affine coordinates.
def to_affine(P):
    x, y, z = P
    if z == 0:
        return None
    zi = pow(z, -1, p)
    return (x * zi * zi % p, y * zi * zi * zi % p)


def point_mul(Pt, k):
    return to_affine(Multiply((Pt[0], Pt[1], 1), k))


def point_add(P1, P2):
    return to_affine(Add((P1[0], P1[1], 1), (P2[0], P2[1], 1)))


Ga = to_affine(G)
Qb = point_mul(Ga, db)
chk = point_add(point_mul(Ga, u1), point_mul(Qb, t1))
print("Bob's first signature verifies with the recovered key:", chk[0] % n == r1)

# --- ECDSA public key recovery for Alice from her first signature.
ra, sa, ca1 = out[0]
z1 = z_of(b"Hello Bob.")
cands = []
for xR in {ra, ra + n}:
    if xR >= p:
        continue
    y2 = (pow(xR, 3, p) + a * xR + b) % p
    y = pow(y2, (p + 1) // 4, p)  # field prime is 3 mod 4
    if y * y % p != y2:
        continue
    for yy in {y, p - y}:
        sR = point_mul((xR, yy), sa)
        zG = point_mul(Ga, z1)
        diff = point_add(sR, (zG[0], (-zG[1]) % p))
        cands.append(point_mul(diff, pow(ra, -1, n)))
print("Alice public key candidates:", len(cands))


def decrypt(ct_int, x):
    key = hashlib.sha256(str(x).encode()).digest()
    L = (ct_int.bit_length() + 7) // 8
    ct = ct_int.to_bytes(L, "big")
    if len(ct) % 16:
        ct = b"\x00" * (16 - len(ct) % 16) + ct
    dec = Cipher(algorithms.AES(key), modes.ECB(), default_backend()).decryptor()
    pt = dec.update(ct) + dec.finalize()
    unpadder = padding.PKCS7(128).unpadder()
    return unpadder.update(pt) + unpadder.finalize()


ca3 = out[2][2]
for i, Qa in enumerate(cands):
    x = point_mul(Qa, db)[0]
    try:
        m1 = decrypt(ca1, x)
    except Exception:
        print(f"candidate {i}: first message does not decrypt")
        continue
    print(f"candidate {i}: first message decrypts to:", m1)
    if m1 == b"Hello Bob.":
        print("flag message:", decrypt(ca3, x).decode())
        sys.exit(0)
raise SystemExit("no candidate worked")
```

## Flag

```text
CTF{But_in_real_life_devs_would_never_use_such_a_buggy_RNG_right?}
```

The flag came out of decrypting Alice's third ciphertext with a key that also decrypts her first ciphertext to the known plaintext and that rests on a private key which re-verifies Bob's signature. Three separate checks, one answer.
